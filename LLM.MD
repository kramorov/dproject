# LLM-интеграция: архитектура и стратегия
> Обсуждение 2026-06-03

## 1. Distillation — своя модель на основе ответов CodeWhale

```
Реальные запросы (client_requests / ручной ввод)
          │
   ┌──────▼──────┐
   │  CodeWhale   │  ← «учитель»: парсинг текста → params JSON + подбор
   │  (DeepSeek   │
   │   V4 Pro)    │  читает БД, вызывает API, ранжирует, объясняет
   └──────┬──────┘
          │ пары «текст → JSON»
   ┌──────▼──────┐
   │  Датасет     │  {"messages": [{"role":"user","content":"..."},
   │  .jsonl      │   {"role":"assistant","content":"{type, params, results}"}]}
   └──────┬──────┘
          │ fine-tune (LoRA)
   ┌──────▼──────┐
   │  Своя модель │  Llama-3-8B / Qwen-2.5-7B / Gemma-2-9B
   │  (локально)  │  запущена на своём сервере, всегда доступна
   └──────────────┘
```

- Fine-tune на одной GPU (RTX 3090/4090 хватит для 7-8B модели)
- Модель учится: понимать технический русский + ГОСТ, выдавать structured JSON
- При отсутствии доступа к CodeWhale — локальная модель продолжает работать

## 2. Function Calling — другие LLM и твой API

Твоя система идеально подходит для function calling:

```json
{
  "name": "search_equipment",
  "description": "Подбор промышленного оборудования по параметрам",
  "parameters": {
    "type": {"enum": ["gearbox", "filter_regulator", "limit_switch"]},
    "ip_id": "степень IP защиты",
    "exd_id": "взрывозащита",
    "work_temp_min": "мин. температура, °C",
    "min_work_torque": "момент на редукторе, Нм",
    ...
  }
}
```

Любой LLM с function calling (GPT-4, Claude, Llama, Qwen) сможет:
1. Понять запрос пользователя
2. Вызвать `search_equipment(params)` → твой API
3. Получить `{exact: [...], compatible: [...]}`
4. Сформулировать ответ с объяснением

**Что нужно:**
- OpenAPI-схема эндпоинтов (DRF даёт её автоматически)
- MCP-сервер (Model Context Protocol) — обёртка над API
- Документация параметров из `FilterDefinition` / `CatalogConfig`

## 3. Почему система интересна LLM

| Фактор | Оценка | Почему |
|--------|--------|--------|
| **Структурированность API** | ★★★★★ | CatalogConfig + FilterDefinition + exact/compatible — готовая function-calling схема |
| **Предметная область** | ★★★★☆ | Промышленная арматура нишева, LLM в ней слабы. Система — источник истины |
| **Локализация** | ★★★★★ | Русский + ГОСТ — LLM нуждаются в grounding, факты которых нет в training data |
| **Exact/compatible** | ★★★★★ | Ранжирование с объяснением — LLM могут объяснять *почему* модель подходит |
| **Масштабируемость** | ★★★★☆ | Паттерн CATALOG_PATTERN.md — новый каталог за час, LLM работает без переобучения |

**Кейс для LLM-провайдеров:** «Промышленный подбор оборудования по ГОСТ» — этого нет у Perplexity, ChatGPT, DeepSeek. Они могут описать что такое редуктор, но не могут сказать «ABRA-BUV-VF826-DN100 подходит, потому что...».

## 4. Три варианта интеграции

| Вариант | Как работает | Плюсы | Минусы |
|---------|-------------|--------|--------|
| **A. Прямые SQL-запросы** | CodeWhale читает db.sqlite3 через Python | Не нужен сервер | В обход exact/compatible, IP-рангов |
| **B. Django REST API** | fetch_url → localhost:8000/api/... | Вся фильтрация работает | Нужен запущенный сервер |
| **C. Management command** | manage.py match_requirements '{"text":"..."}' → JSON | Сервер не нужен, логика intact | Нужно написать команду |

Рекомендация: **B для продакшена, C для разработки**.
