# AUTORUN 报价系统261119 — описание системы и карта данных

Документ описывает китайскую систему подбора/расчёта приводов («报价系统» =
quotation system, бренд AUTORUN / 欧德隆 Oudelong), чтобы перенести из неё
данные и логику в наш проект. Сопутствующие артефакты лежат рядом с этим файлом
(перевод интерфейса — см. `README.md`).

---

## 1. Что это за система

- **Назначение**: подбор пневмоприводов по требуемому моменту/усилию клапана и
  расчёт цены (спецификация + итоговая заказная модель + цена с наценками).
- **Название в окне**: 欧德隆执行器智能选型系统 — «Интеллектуальная система
  подбора приводов Oudelong».
- **Линейки приводов** (строка из самой программы):
  `BTS 大口径拨叉 · NRT 小口径齿轮齿条 · BTL 直行程`:
  - **BTS** — скотч-йок (拨叉式), ротационные, крупный калибр;
  - **NRT** — шестерня-рейка (齿轮齿条), ротационные, малый калибр (бренд RICHTORK);
  - **BTL** — линейные (直行程).
- **Технологии**: Python 3.11 + PySide6 (Qt GUI) + openpyxl + SQLite, упаковано
  PyInstaller (one-dir).

        │  чтение
        ▼

`quotation.db`:
- таблица `metadata` (`key` TEXT, `value` TEXT): `source_sha256`, `updated_at`;
- таблица `records` (`category` TEXT, `record_key` TEXT, `payload` TEXT — JSON).

**Важно**: приложение читает данные из `quotation.db`, а не напрямую из
`data.json`. Если SHA-256 `data.json` изменился — переимпортирует. Поэтому для
перевода/правки данных нужно менять **оба** файла (локальный `data.json` и БД).

## 5. Ротационные приводы (`rotary`)

Формат записи:
```json
{
  "id": "rotary:BTS1-200:0.3",
  "model": "BTS1-200",
  "action": "double",           // double | single
  "pressure": 0.3,               // МПа
  "air":    [1002, 520, 1002],   // момент от воздуха: старт/середина/конец хода
  "spring": null,                // момент пружины (для single) или null
  "price": { ... },              // см. §9
  "source": {"file": "...", "sheet": "...", "row": 4}
}
```

Две линейки (по коду модели):
- **BTS** (819 записей, `family` отсутствует) — скотч-йок. Модели `BTS1..BTS8`,
  размеры до ~350. Пример `BTS1-250-90-2K/B` (угол 90°, набор пружин `2K`).
- **NRT** (665 записей, `family="NRT"`) — шестерня-рейка. Модели
  `NRT032D..NRT400D` (double) и `NRT52S08..` (single, суффикс `S08/S09/S10` =
  число пружин).

Для single-приводов `spring[3]` = момент пружины в 3 точках; `air[3]` = момент
воздуха в 3 точках. Это «трёхточечная» кривая момента, а не одна цифра.

## 6. Линейные приводы (BTL) — все настройки

### 6.1. Модель и усилие (`linear`, 210 записей)
```json
{"id":"linear:BTL125:double:0.3","model":"BTL125","action":"double",
 "pressure":0.3,"air":3385.3,"spring":null,"source":{...}}
```
- `model`: `BTL80 … BTL1000` (30 типоразмеров). Есть варианты с суффиксом
  `B`/`b` (например `BTL220B`, `BTL200b`) — другая конфигурация поршня/штока.
- `action`: `double` (120) / `single` (90).
- `pressure`: только 0.3 / 0.4 / 0.5 / 0.6 МПа.
- `air`: усилие от воздуха (Н). Для `single` дополнительно `spring` (Н) —
  усилие пружины в той же точке.

### 6.2. Цены (`linearPrices`, 447 записей)
Ключ `действие:модель:ход`, значение:
```json
{"model":"BTL125","stroke":50,"price":672,"source":{...}}
```
- `stroke` (ход, мм) — дискретные значения 30…950.
- `price` — базовая цена модели с этим ходом.
- Цена считается интерполяцией/экстраполяцией между опорными точками хода
  (в коде: «mm参考价线性计算», «mm价格斜率线性外推» — линейная интерполяция/наклон).

### 6.3. Готовые конфигурации (`linearManualConfigurations`, 309 записей)
```json
{"valveType":"气动截止阀","dn":"25","pnNumbers":["16"],"action":"double",
 "pressure":0.4,"actuatorFamily":"BTL80","stroke":30.0,
 "actuatorModel":"BTL80-W30-D04-N0","actuatorPrice":535.0,
 "manualOptions":[{"name":"中置手动","price":400.0,"status":"可报价"}],
 "source":{"sheet":"气动截止阀",...}}
```
- `valveType` (тип клапана): `气动截止阀` (запорный), `气动刀闸阀` (шиберная),
  `气动平板闸阀` (плоский шибер), `气动楔式闸阀` (клиновая задвижка).
- `dn`, `pnNumbers`, `pressure`, `stroke` — условия применения.
- `actuatorFamily` — семейство привода (`BTL80…BTL900` + `B`/`b` варианты).
- `actuatorModel` — итоговая заказная модель (см. §6.4).
- `actuatorPrice` — цена привода.
- `manualOptions[]` — доступные ручные дублёры: `name` + `price` + `status`
  (`可报价` = можно рассчитать цену, `待确认` = требует подтверждения).

### 6.4. Кодировка заказной модели BTL
`actuatorModel` вида `BTL125-W30-D04-N0`:
```
BTL<диаметр цилиндра> - <структура><ход> - <действие><код давления> - N<ручной дублёр>
```
- **Диаметр цилиндра (缸径)**: 80–1200 мм (в данных 80–1000). Ошибка вне этого
  диапазона → сообщение «BTL缸径超出订货资料规定的80–1200 mm范围».
- **Структура (拉杆结构)**: `N` = 内置拉杆 (встроенная тяга), `W` = 外置拉杆
  (внешняя тяга). В данных все записи `W`.
- **Ход (行程)**: 10–2000 мм, целое число (в данных 30–950).
- **Действие (作用方式)**: `D` = double (双作用), `K` = single/пружинный возврат
  (单作用弹簧复位).
- **Код давления**: `03/04/05/06` → 0.3/0.4/0.5/0.6 МПа.
- **Ручной дублёр (手动机构)**: `N0` = нет, `N2`/`N4` и т.д. (код 0–5).

### 6.5. Ручные дублёры (manualOptions)
Справочник типов ручного дублёра (название → русский):
| Китайский | Русский |
|---|---|
| 中置手动 | центральный ручной |
| 顶置插销丝杆 | верхний шплинт со шпинделем |
| 顶置插销伞齿轮 | верхний шплинт с конической передачей |
| 顶置丝杆/插销 | верхний шпиндель/шплинт |
| 顶置伞齿轮 插销/离合 | верхняя коническая передача, шплинт/муфта |
| 顶置伞齿轮 插销/离合 /液压 | то же + гидравлика |
| 插销丝杆 / 插丝杆 / 插杆 / 插销 | шплинт/шпиндель, вставной шпиндель, вставной шток, шплинт |
| 伞齿轮 / 伞齿 | коническая передача |
| 液压手动 / 液压 | гидравлический ручной / гидравлический |

Коды ручного дублёра в заказной модели (из кода): `0`=不配置 (нет),
`1`=丝杆 (шпиндель), `2`=伞齿轮 (коническая передача), `3`=离合 (муфта),
`4`=液压 (гидравлика).

### 6.6. Спец. исполнение (特殊定制)
Коды `00–07`:
- `00` = 默认 (по умолчанию);
- `01` = 限制气缸模组 (ограничение модуля цилиндра);
- `02` = 限制弹簧模组 (ограничение пружинного модуля);
- `03` = 同时限制 (ограничение обоих);
- `04` = 高频/高频次 (высокая частота);
- `05` = 高频/开限位 (высокая частота + концевик открытия);
- `06` = 高频/关限位 (высокая частота + концевик закрытия);
- `07` = 高频/开关限位 (высокая частота + оба концевика).

## 7. Шеститочечный расчёт момента (ротационные)

Формула в коде: `六点需求 = 基准扭矩 × 厂家动作系数`
(шеститочечная потребность = базовый момент × коэффициент действия производителя).

6 точек — это кривая момента клапана по ходу (Break/Run/End × Open/Close):
`BTO, RTO, ETO, BTC, RTC, ETC`.

Коэффициенты по типу клапана (`coefficients[].factors`, массив из 6):
| Тип клапана | factors (BTO..ETC) |
|---|---|
| 浮动式软密封球阀 (плавающий, мягкое) | 1.0, 0.6, 0.9, 0.9, 0.6, 1.0 |
| 浮动式硬密封球阀 | 1.0, 0.7, 0.9, 0.9, 0.7, 1.0 |
| 固定式软密封球阀 (с цапфами, мягкое) | 1.0, 0.55, 0.9, 0.9, 0.55, 1.0 |
| 固定式硬密封球阀 | 1.0, 0.65, 0.9, 0.9, 0.65, 1.0 |
| 软密封蝶阀 (дисковый, мягкое) | 1.0, 0.4, 0.35, 0.35, 0.4, 1.0 |
| 硬密封蝶阀 | 1.0, 0.4, 0.35, 0.35, 0.4, 1.0 |
| 旋塞阀 (пробковый) | 1.0, 0.9, 1.0, 1.0, 0.9, 1.0 |
| 高性能蝶阀PTFE | 1.0, 0.4, 0.35, 0.35, 0.4, 1.0 |

Также есть `values` (диапазоны вида `80%~90%`) и `minimumFactors` (нижние границы).
Порядок точек соответствует `BTO, RTO, ETO, BTC, RTC, ETC`.

Дополнительно есть `valveTorqueLookup` — таблицы базового момента клапана по
DN/PN (12 значений момента на пару DN/PN: 6 PN-классов × 2 таблицы). При отсутствии
значения в таблице → подбор «по базовому моменту» вручную.

## 8. Четырёхточечный расчёт усилия (линейные)

Для линейных применяется «четырёхточечное усилие» (四点推力). В коде для
шиберной задвижки:
`气动刀闸阀 · 四点系数 1 / 0.45 / 0.5 / 1，按 BTO、ETC 选缸径`
— четырёхточечные коэффициенты **1 / 0.45 / 0.5 / 1**, подбор цилиндра по BTO и ETC.

Точки для линейных (из полей записи/кода): BTO / RTO / ETO / BTC / RTC / ETC
аналогично ротационным, но для подбора линейного привода используется 4 точки
(четырёхточечное усилие). Расчёт: потребное усилие в каждой точке = базовое
усилие × коэффициент; привод должен покрыть все точки (`air`/`spring`).

## 9. Конструктор цен

### 9.1. Ротационные
`rotary[].price`:
```json
{"priceModel":"NRT-52-S08","basePrice":106.0,
 "handModel":null,"handPrice":null,"handOptions":[],
 "extraSurcharges":{"整体喷塑涂料":10.0,"船舶及近海级涂料":30.0,"304轴":50.0,"316L轴":55.0},
 "lowTempSurcharge":13.0,"highTempSurcharge":13.0,"sourceCell":"序号3"}
```
Формула:
```
цена = basePrice
     + Σ(выбранные extraSurcharges)     # опции
     + lowTempSurcharge | highTempSurcharge   # температурное исполнение
     + handPrice                        # ручной дублёр
```
- `extraSurcharges`: 整体喷塑涂料 (полная порошковая окраска),
  船舶及近海级涂料 (морское/оффшорное покрытие), 304轴 (вал 304), 316L轴 (вал 316L).
  Это фиксированные суммы (растут с типоразмером), не проценты.
- `handModel`/`handPrice` — ручной дублёр (у BTS есть, у NRT double — null).
- `priceModel` — артикул цены (для прайса).

### 9.2. Линейные
- Базовая цена привода — `linearPrices` по ключу `действие:модель:ход`
  (интерполяция по ходу).
- Готовые конфигурации — `linearManualConfigurations[].actuatorPrice`
  + `manualOptions[].price` (цена ручного дублёра).
- Статус цены: `可报价` (можно рассчитать) / `待确认` (запрос) / `待询价`
  (запрос цены).

## 10. Что переносить в наш проект

1. **Ротационные приводы** — `rotary`: таблицы момента `air[3]/spring[3]` по
   давлению + цены. BTS (скотч-йок) и NRT (рейка) разделяются по коду модели.
2. **Линейные приводы** — `linear` (усилие) + `linearPrices` (цена по ходу) +
   `linearManualConfigurations` (готовые конфигурации, ручные дублёры) + кодировка
   заказной модели BTL.
3. **Шеститочечный расчёт** — `coefficients[].factors` (8 типов клапанов) +
   `valveTorqueLookup` (момент по DN/PN).
4. **Четырёхточечный расчёт** — коэффициенты для линейных (1 / 0.45 / 0.5 / 1 для
   шиберной задвижки).
5. **Конструктор цен** — схема `basePrice + наценки опций + температурная наценка
   + ручной дублёр`.

Самый надёжный способ получить данные — экспорт из самой программы (JSON/Excel,
см. §11): он даёт актуальный канон, а не распакованный `data.json`.

## 12. План переноса (задачи и промежуточные шаги)

### Общая подготовка (шаг 0, для всех задач)
1. Получить из программы **полный системный JSON** («导出完整系统资料» →
   `报价系统资料.json`) — это актуальный канон, а не распакованный `data.json`.
2. Сохранить его как эталон и написать один парсер `data.json`-структуры
   (Python, без Django-зависимостей), который выдаёт нормализованные dict'ы по
   категориям `coefficients`, `valveTorqueLookup`, `linear*`.
3. Зафиксировать маппинг китайских типов клапанов → наши `params.ValveTypes`
   (единый справочник соответствий, используется во всех трёх задачах).

### Задача 1 — шеститочечные коэффициенты (`coefficients`, 8 записей)
**Цель**: реализовать в нашем подборе ПП расчёт требуемого момента по 6 точкам
(BTO/RTO/ETO/BTC/RTC/ETC) вместо текущего примитивного.

Промежуточные шаги:
1. Распарсить `coefficients` → `{тип_клапана: {values, minimumFactors, factors}}`.
2. Создать модель/справочник (в `pneumatic_actuators`):
   `ValveTorqueCoefficient(valve_type → FK params.ValveTypes, factors[6],
   minimum_factors[6], values_display[6])` — 6 дробных полей (или JSON) на запись.
3. Загрузить 8 типов клапанов (маппинг: 浮动式软密封球阀 → «кран шаровый
   плавающий, мягкое уплотнение», 固定式… → «с цапфами», 蝶阀 → «дисковый затвор»,
   …). Типы, которых у нас нет — завести в `params.ValveTypes`.
4. Реализовать расчёт: `требуемый момент[i] = базовый момент × factors[i]` для
   6 точек; выбор привода — покрыть все 6 точек его кривой `air[3]/spring[3]`
   (у нас это уже есть как `BodyThrustTorqueTable` с `bto/rto/eto`).
5. Подключить в селектор ПП (`pneumatic_actuators` / подбор «по моменту»),
   заменив примитивный расчёт; поддержать `minimumFactors` (нижняя граница) и
   диапазонные `values` (типа `80%~90%`) как настраиваемые вводы.
6. Тесты: 8 типов клапанов × несколько DN — сверка ожидаемых моментов.

### Задача 2 — таблицы базового момента по DN/PN (`valveTorqueLookup`)
**Цель**: подбор «по моменту» без ручного ввода базового момента — момент клапана
берётся из таблицы по (тип клапана, DN, PN/class).

Промежуточные шаги:
1. Распарсить `valveTorqueLookup`: `pressureRatings` (12), `tables` (8 типов
   клапанов), `rows[]` → `{nps, dn, torques[12]}`.
2. Понять и зафиксировать порядок `torques[12]` ↔ `pressureRatings[12]`
   (12 колонок = PN-ряд + class-ряд; см. `notes`).
3. Построить lookup: `(тип_клапана, dn, pn/class) → базовый_момент` (плоская
   таблица в нашей БД, например `ValveTorqueLookup` в `valve_data` или
   `pneumatic_actuators`).
4. Маппинг PN/class → наши справочники давления; типы клапанов — тот же маппинг
   из шага 0.3.
5. Интегрировать в подбор: если значение есть в таблице — брать его, иначе —
   fallback на ручной «базовый момент» (как сейчас), с пометкой «нет табличного
   значения» (в исходнике это «/»).
6. Замечание по источникам: это **обобщённые** данные (TY шаровые, Оните дисковые,
   мягкое уплотнение). Оставить возможность переопределения под конкретного
   производителя позже (приоритет производителя > обобщённая таблица).
7. Тесты: пары DN/PN с известными значениями + пустые ячейки.

### Задача 3 — каркас линейных приводов (`linear` + `linearPrices` +
`linearManualConfigurations`, 309 готовых связок)
**Цель**: адаптировать наши модели линейных приводов под структуру BTL.

Промежуточные шаги:
1. Распарсить `linear` (усилие по диаметру/давлению), `linearPrices` (цена по
   ходу), `linearManualConfigurations` (готовые связки).
2. Спроектировать модель линейного привода в `pneumatic_actuators` (аналог
   `PneumaticActuatorBody` для линейных): типоразмер/цилиндр (диаметр 80–1200),
   структура N/W (встроенная/внешняя тяга), ход, действие D/K (двойное/пружинный
   возврат), давление 0.3–0.6, ручной дублёр, усилие `air`/`spring`.
3. Маппинг типов клапанов (气动截止阀/刀闸阀/平板闸阀/楔式闸阀) и ручных дублёров
   (中置手动, 顶置插销丝杆, …) в наши справочники (как в §6.5).
4. Импортировать 309 конфигураций как **готовые карточки** «тип клапана × DN/PN ×
   давление → привод × ручной дублёр × цена» — это стартовый каталог линейных
   моделей, который потом дополняется производителями.
5. Сверить кодировку `BTL80-W30-D04-N0` (§6.4) с нашей логикой кодировок (артикул

6. Тесты: несколько конфигураций — сверка модели/усилия/цены.

### Порядок и зависимости
- Задачи 1 и 2 независимы; обе используют общий маппинг типов клапанов (шаг 0.3).
- Задача 3 опирается на справочники ручных дублёров и типов клапанов (шаг 0.3 +

## 13. Текущее состояние и дальнейший план (актуализировано 2026-11-20)

### 13.1. Что уже сделано в нашем проекте

Модели — в приложении **`valve_data`** (файл `models/torque_characteristics.py`), а не
в `pneumatic_actuators` (как предполагалось в §12): характеристики относятся к арматуре,
поэтому логично живут в `valve_data`.

- **`TorqueThrustCharacteristics`** — справочник наборов характеристик момента/усилия.
  Поле `motion_type` → FK на общий справочник **`ActingType`** (`pa_controls`, коды
  `LINEAR`/`ROTARY`) — определяет 6 точек (rotary) или 4 точки (linear).
- **`ValveTorqueCoefficient`** — коэффициенты `BTO/RTO/ETO/BTC/RTC/ETC` (6 Decimal) +
  `minimum_factors` + `values_display` (JSON). Составной ключ:
  `valve_type` (FK `params.ValveTypes`) + `support` (FK `ValveSupportType`) +
  `seal_type` (FK `SealType`).
- **`ValveSupportType`** — опора пробки: `floating` («с плавающей пробкой») /
  `trunnion` («на цапфах»).
- **`SealType`** — тип уплотнения: `soft` («мягкое, NBR/EPDM и др.») / `hard`
  («жёсткое, металл-металл») / `ptfe`.

Единый классификатор «ротационный/линейный» — **`ActingType`** (не дублируем):
используется и позиционерами (`pa_controls`), и характеристиками момента. Ему добавлен
`OptionListToSelectMixin` (для `get_for_select`).

### 13.2. Маппинг 8 типов AUTORUN → наша модель

| AUTORUN (кит.) | valve_type | support | seal_type |
|---|---|---|---|
| 浮动式软密封球阀 | кран шаровый | floating | soft |
| 浮动式硬密封球阀 | кран шаровый | floating | hard |
| 固定式软密封球阀 | кран шаровый | trunnion | soft |
| 固定式硬密封球阀 | кран шаровый | trunnion | hard |
| 软密封蝶阀 | дисковый затвор | — | soft |
| 硬密封蝶阀 | дисковый затвор | — | hard |
| 旋塞阀 | кран пробковый | — | — |
| 高性能蝶阀PTFE | дисковый затвор | — | ptfe |

В `params.ValveTypes` добавлена запись `plug-valve` («Кран пробковый»).

Терминология (кит. → англ. → рус.):
- 浮动式 → floating → «с плавающей пробкой» (floating ball);
- 固定式 → trunnion → «на цапфах» (trunnion-mounted);
- 软密封 → soft → «мягкое уплотнение» (soft seat);
- 硬密封 → hard → «жёсткое, металл-металл» (metal seat).
