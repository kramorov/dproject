# OCR — распознавание документов (текст / таблицы / опросные листы)

Инструмент «Распознавание (OCR)» предназначен для извлечения данных из сканов
документов: произвольного текста, таблиц и опросных листов (ОЛ) с чек-боксами.
Фронтенд: `http://localhost:5173/tools/table-ocr`.

---

## 1. Три режима работы

Интерфейс разделён на три режима (вкладки сверху), каждый под свой тип результата:

| Режим | Назначение | Результат |
|-------|-----------|-----------|
| **Текст** | Извлечь текст из изображения/PDF | Копирование текста в буфер |
| **Таблица** | Распознать таблицу | Таблица на экране + копирование (TSV) + Excel |
| **ОЛ (разметка)** | Ручная разметка опросного листа | Дерево «раздел → поле → значение» → JSON / Word / Excel |

Во всех режимах доступна **лупа** (3× увеличение) для точного просмотра и
выделения мелких фрагментов.

---

## 2. Связь компонентов (общая схема)

```
Frontend (Vue)                          Backend (Django REST)
─────────────────                       ─────────────────────
frontend/src/pages/TableOcrTool.vue
  │  режимы: Текст / Таблица / ОЛ
  │
  ├─ Текст / Таблица ──────────────►  POST /ocr/recognize/      ─►  media_library/table_extractor.py
  │   (выделение области, параметры)        (img2table + RapidOCR)
  │
  ├─ ОЛ: разметка (раздел/поле/      ►  POST /ocr/region/        ─►  media_library/form_extractor.py
  │   таблица f-v / значение)              (kind=text|value|fvtable)  (чек-боксы, сетка, OCR текста)
  │
  ├─ Экспорт разметки (JSON) ──────►  POST /ocr/export-structure/ ─► media_library/form_export.py
  │                                          (Word / Excel)
  │
  └─ Экспорт распознавания ────────►  POST /ocr/export/         ─►  table_extractor.py
        (result_id, xlsx/docx)                                   (result_to_excel/docx_bytes)
```

Управляющие настройки — в `djangoProject1/settings.py`:

- `MEDIA_TABLE_OCR_BACKEND` (env `MEDIA_TABLE_OCR_BACKEND`, по умолчанию `rapidocr`) —
  какой OCR-движок используется по умолчанию для таблиц/текста.
- `MEDIA_OCR_MODEL_DIR` (env `MEDIA_OCR_MODEL_DIR`) — каталог ONNX-моделей RapidOCR
  (для Docker/volume: модели не скачиваются заново при каждом запуске).

## 3. Бэкенд-модули

### `media_library/table_extractor.py`
Распознавание **текста и таблиц** через `img2table` с подключаемыми OCR-движками.

- `OCR_BACKENDS` — реестр движков: `tesseract`, `rapidocr`, `surya`, `paddle`,
  `easyocr`, `doctr` (импортируются лениво, чтобы отсутствие библиотеки не роняло
  Django).
- `_rapidocr_params()` — параметры RapidOCR. По умолчанию подключается
  восточнославянская rec-модель `eslav_PP-OCRv5_rec_mobile` (кириллица + латиница +
  цифры), потому что стандартная английская модель не распознаёт русский текст.
- `recognize_pages()` — постраничное распознавание: текст + таблицы.
- `extract_tables()` / `tables_to_preview()` — таблицы в виде словарей для JSON.
- `result_to_excel_bytes()` / `result_to_docx_bytes()` — экспорт результата
  распознавания в Excel/Word.

### `media_library/form_extractor.py`
Разбор **областей изображения** для опросных листов (без табличного контекста).

- `_detect_checkboxes()` — поиск квадратных чек-боксов (контуры с 4 углами) и
  определение состояния «отмечен/пуст» по доле тёмных пикселей внутри квадрата.
  Размер чек-бокса определяется автоматически (кластеризация по медианному
  размеру), поэтому алгоритм не привязан к конкретному разрешению/DPI.
- `_has_table_grid()` — отличает таблицу от набора чек-боксов по длинным
  горизонтальным линиям (морфология OpenCV).
- `analyze_region()` — автоопределение типа значения области в порядке
  **таблица → чек-боксы → текст**.
- `extract_fv_table()` — таблица из двух столбцов → список пар `{field, value}`
  (граница столбцов ищется по максимальному горизонтальному разрыву между словами).
- `ocr_text_in_area()` / `ocr_text_in_region()` — OCR текста в области.

### `media_library/form_export.py`
Экспорт размеченной структуры ОЛ (JSON-дерева) в файлы:

- `structure_to_xlsx()` — колонки «Раздел / Поле / Значение».
- `structure_to_docx()` — заголовки разделов, строки `поле: значение`, таблицы.

### `media_library/views/admin_ocr_tool.py`
REST-представления (все под правами `admin_section`):

- `MediaOcrRecognizeView` — распознавание файла целиком (или выделенной области).
- `MediaOcrRegionView` — разбор одной области (`kind=text|value|fvtable`).
- `MediaOcrExportView` — выгрузка результата распознавания (`result_id`).
- `MediaOcrStructureExportView` — выгрузка структуры разметки (Word/Excel).
- `MediaOcrCheckboxLabelView` — устаревший/запасной endpoint OCR подписи чек-бокса.

### `media_library/urls.py`
Маршруты (внутри `api/admin/media/`):

```
ocr/recognize/          POST — распознавание файла/области
ocr/region/             POST — разбор области (text/value/fvtable)
ocr/export/             POST — экспорт результата (xlsx/docx)
ocr/export-structure/   POST — экспорт структуры разметки (xlsx/docx)
ocr/checkbox-label/     POST — OCR подписи чек-бокса (запасной)
```

### `media_library/management/commands/preload_ocr_models.py`
`python manage.py preload_ocr_models [--lang=eslav]` — предзагрузка ONNX-моделей
RapidOCR (детекция + классификация + распознавание). Нужно при сборке Docker-образа,
чтобы модели лежали в volume и не скачивались в рантайме.

## 4. OCR-движки

По умолчанию используется **RapidOCR** (onnxruntime, без системного tesseract и
без torch) — лёгкий и удобный для Docker. Для кириллицы подключена модель
`eslav_PP-OCRv5_rec_mobile`.

| Движок | Зависимости | Примечание |
|--------|-------------|------------|
| `rapidocr` | `rapidocr`, `onnxruntime` | по умолчанию, кириллица (eslav) |
| `tesseract` | системный бинарь `tesseract` + языковые пакеты | нужен apt/path, не pip-only |
| `easyocr` | `easyocr`, `torch` | тяжёлый (~2 ГБ) |
| `paddle` | `paddleocr`, `paddlepaddle` | тяжёлый |
| `surya` | `surya-ocr`, `torch` | тяжёлый |
| `doctr` | `python-doctr` | — |

## 5. Алгоритмы (ключевые)

### 5.1 Чек-боксы
1. Бинаризация (адаптивный порог) → контуры.
2. Отбор квадратов: 4 угла после аппроксимации, соотношение сторон ~1,
   заполненность bounding box ≥ порога.
3. Кластеризация по медианному размеру (убирает шум от букв/цифр).
4. Дедупликация внешней/внутренней рамки.
5. Состояние: доля тёмных пикселей во внутренней области (бинаризация Оцу)
   `> 0.08` → «отмечен».

### 5.2 Разбор области значения (`analyze_region`)
Порядок: **таблица → чек-боксы → текст**.
- Таблица — если есть ≥ 4 длинных горизонтальных линий (сетка).
- Чек-боксы — если найдены квадраты.
- Иначе — OCR текста (с сохранением переносов строк).

### 5.3 Таблица field-value (`extract_fv_table`)
1. OCR слов с координатами.
2. Группировка слов по строкам (близость по Y).
3. Граница двух столбцов — максимальный горизонтальный разрыв между словами.
4. Слова слева → `field`, справа → `value`.

## 6. Формат JSON разметки ОЛ

Выход ручной разметки (готов под анализ нейросетью и под экспорт):

```json
{
  "items": [
    {
      "kind": "section",
      "title": "ОБЩИЕ ДАННЫЕ",
      "children": [
        {
          "kind": "field",
          "field": "Предприятие",
          "values": [
            { "type": "text", "text": "ООО «ЮГАЗ-Инжиниринг»" }
          ]
        }
      ]
    },
    {
      "kind": "field",
      "field": "Характеристика рабочей среды",
      "values": [
        {
          "type": "checkboxes",
          "selected": ["Взрывоопасная", "Пожароопасная"],
          "options": [
            { "label": "Взрывоопасная", "checked": true },
            { "label": "Пожароопасная", "checked": true },
            { "label": "Токсичная", "checked": false }
          ]
        }
      ]
    },
    {
      "kind": "table",
      "rows": [
        { "field": "Метан", "value": "0,9720" },
        { "field": "Этан", "value": "0,0018" }
      ]
    }
  ]
}
```

Узлы:
- `section` — название раздела, может содержать вложенные `children`.
- `field` — пара поле–значение; `values` может быть несколько (текст / чек-боксы / таблица).
- `table` — таблица из двух столбцов, развёрнутая в список `rows` (field/value).

## 7. Работа в режиме «ОЛ (разметка)»

1. Загрузить изображение.
2. Кнопками `＋ Раздел`, `＋ Поле`, `＋ Таблица F-V`, `＋ Значение` выбрать действие
   и обвести область на превью (зажать левую кнопку мыши, растянуть, отпустить).
3. Область распознаётся автоматически, фрагмент появляется в **ленте** справа:
   миниатюра области + текст + тип.
4. В ленте фрагменты можно переупорядочивать (drag-and-drop, `↑/↓`), менять
   вложенность (`↳/↰`), удалять (`✕`). Новые разделы/поля попадают внутрь активного
   раздела, значения — в активное поле.
5. Экспорт: `📋 JSON` / `💾 JSON` / `💾 Excel` / `💾 Word`.

## 8. Ограничения

- Качество OCR зависит от модели: возможны ошибки в похожих символах
  (`1`↔`I`, `3`↔`з`, `газ`→«ра3», `зона`→«3она»).
- Объединённые ячейки таблиц `img2table` «сплющивает» в прямоугольную сетку
  (текст извлекается, но без метаданных colspan/rowspan).
- Таблица field-value: граница столбцов по максимальному разрыву — для 2 столбцов
  работает, но на длинных многословных полях возможны ошибки.
- Разметка ОЛ — только для изображений (PDF без превью).
- Drag-and-drop в ленте — перестановка внутри одного уровня; перенос между
  уровнями — кнопками `↳/↰`.
