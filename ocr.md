# OCR — распознавание документов (единая структура: разделы / текст / таблицы)

Инструмент «Распознавание (OCR)» извлекает данные из сканов: пользователь
обводит фрагменты изображения, а они складываются в **единую структуру** —
одновременно задание для распознавания и форму результата. Отдельных вкладок
(«Текст» / «Таблица» / «ОЛ») больше нет. Поддерживаются **изображения и PDF**
(PDF разбивается на страницы, разметка привязана к страницам).

Фронтенд: `http://localhost:5173/tools/table-ocr`.

---

## 1. Концепция

Слева — изображение для распознавания, справа — **холст** со структурой.
Между ними — кнопки выбора инструмента выделения.

Единая сущность — **структура**. Внутри неё могут быть:

| Узел | Назначение |
|------|-----------|
| **Раздел** (`section`) | Название раздела; начало блока. Содержит вложенные узлы |
| **Текст** (`text`) | Произвольный распознанный текст |
| **Таблица F-V** (`table` + `variant=fv`) | Два столбца: поле → значение |
| **Таблица** (`table` + `variant=grid`) | Классическая: несколько строк × несколько столбцов. Заголовки столбцов могут быть в первой строке (опция «шапка»), а могут отсутствовать |

Правила:

- **Головной раздел всегда пустой** (без названия) — это корень холста.
  Если ни одного названия раздела не выделено, все фрагменты попадают в него.
- **Началом блока является выделение раздела**: новый раздел становится
  активным, и следующие выделения (текст, таблицы) попадают внутрь него.
- **Блоки в холсте двигаются мышкой** (drag-and-drop): можно менять порядок
  и переносить блок из одного существующего раздела в другой (бросить на
  раздел — попасть внутрь, бросить на другой блок — встать перед ним,
  бросить на «Главный раздел» — выйти на верхний уровень).
- **Холст = задание распознавания и структура результата одновременно**:
  при выделении фрагмента он сразу распознаётся и встаёт в структуру.
  Кнопка `⟳ Распознать всё` перезапускает распознавание всех блоков одним
  батч-запросом (см. `/ocr/regions/`).
- Каждый блок привязан к **странице** (для изображения — страница 1) и хранит
  **область** в пикселях этой страницы — это основа будущей обучающей выборки.
- В результат выводятся **структурированный JSON** (с геометрией, `schema_version`
  и метаданными документа) и **распознанный текст** (плоская выгрузка структуры),
  плюс экспорт в Excel / Word.

## 2. Связь компонентов (общая схема)

```
Frontend (Vue)                          Backend (Django REST)
─────────────────                       ─────────────────────
frontend/src/pages/TableOcrTool.vue
  │  изображение/PDF-страницы | инструменты | холст
  │
  ├─ PDF → страницы ─────────────►  POST /ocr/pages/          ─►  рендер страниц (fitz, 200 dpi)
  │   (страницы отдаются отдельно)    GET /ocr/pages/<token>/<n>/
  │
  ├─ Раздел / Текст ─────────────►  POST /ocr/region/        ─►  media_library/form_extractor.py
  │   (обводка области)                 (kind=text)               (OCR текста области)
  │
  ├─ Таблица F-V ────────────────►  POST /ocr/region/        ─►  media_library/form_extractor.py
  │                                  (kind=fvtable)              (extract_fv_table)
  │
  ├─ Таблица (классическая) ─────►  POST /ocr/recognize/     ─►  media_library/table_extractor.py
  │   (region + шапка/без линий)       (img2table + RapidOCR)
  │
  ├─ ⟳ Распознать всё ───────────►  POST /ocr/regions/       ─►  form_extractor + table_extractor
  │   (батч: файл + N регионов)        (один проход на страницу)
  │
  └─ Экспорт структуры ──────────►  POST /ocr/export-structure/ ─► media_library/form_export.py
        (JSON-структура, xlsx/docx)                                 (structure_to_xlsx/docx)
```

Управляющие настройки — в `djangoProject1/settings.py`:

- `MEDIA_TABLE_OCR_BACKEND` (env `MEDIA_TABLE_OCR_BACKEND`, по умолчанию `rapidocr`) —
  какой OCR-движок используется по умолчанию.
- `MEDIA_OCR_MODEL_DIR` (env `MEDIA_OCR_MODEL_DIR`) — каталог ONNX-моделей RapidOCR
  (для Docker/volume: модели не скачиваются заново при каждом запуске).

## 3. Бэкенд-модули

### `media_library/table_extractor.py`
Распознавание **таблиц и текста** через `img2table` с подключаемыми OCR-движками.

- `OCR_BACKENDS` — реестр движков: `tesseract`, `rapidocr`, `surya`, `paddle`,
  `easyocr`, `doctr` (импортируются лениво).
- `_rapidocr_params()` — параметры RapidOCR. По умолчанию подключается
  восточнославянская rec-модель `eslav_PP-OCRv5_rec_mobile` (кириллица + латиница +
  цифры), потому что стандартная английская модель не распознаёт русский текст.
- `recognize_pages()` — постраничное распознавание: текст + таблицы.
- `extract_tables()` / `tables_to_preview()` — таблицы в виде словарей для JSON.
- `crop_image_bytes()` — вырезка области изображения (для распознавания фрагмента).
- `result_to_excel_bytes()` / `result_to_docx_bytes()` — экспорт результата
  распознавания в Excel/Word.

### `media_library/form_extractor.py`
Разбор **областей изображения** для разметки (без табличного контекста).

- `_detect_checkboxes()` — поиск квадратных чек-боксов (контуры с 4 углами) и
  определение состояния «отмечен/пуст» по доле тёмных пикселей внутри квадрата.
- `_has_table_grid()` — отличает таблицу от набора чек-боксов по длинным
  горизонтальным линиям (морфология OpenCV).
- `analyze_region()` — автоопределение типа значения области в порядке
  **таблица → чек-боксы → текст** (запасной режим, в новой схеме не используется).
- `extract_fv_table()` — таблица из двух столбцов → список пар `{field, value}`
  (граница столбцов ищется по максимальному горизонтальному разрыву между словами).
- `ocr_text_in_area()` / `ocr_text_in_region()` — OCR текста в области.

### `media_library/form_export.py`
Экспорт структуры (JSON-дерева) в файлы:

- `structure_to_xlsx()` — колонки «Раздел / Поле / Значение»; классические
  таблицы выносятся на отдельные листы «Таблица N».
- `structure_to_docx()` — заголовки разделов, абзацы текста, пары
  `поле: значение`, таблицы (F-V и классические).

### `media_library/views/admin_ocr_tool.py`
REST-представления (все под правами `admin_section`):

- `MediaOcrRecognizeView` — распознавание файла целиком (или выделенной области).
- `MediaOcrRegionView` — разбор одной области (`kind=text|value|fvtable`).
- `MediaOcrRegionsView` — **батч**: файл один раз + JSON-массив регионов
  (`kind=text|fvtable|grid`), ответ сопоставляется по `id`.
- `MediaOcrPagesView` — **страницы документа**: `POST` файл (PDF → PNG по
  страницам, 200 dpi; изображение → одна страница), `GET /<token>/<n>/` отдаёт
  PNG страницы. Разметка PDF ведётся по этим страницам.
- `MediaOcrExportView` — выгрузка результата распознавания (`result_id`).
- `MediaOcrStructureExportView` — выгрузка структуры (Word/Excel).
- `MediaOcrCheckboxLabelView` — устаревший/запасной endpoint OCR подписи чек-бокса.

Токены результатов и страниц **привязаны к владельцу** (`user.pk` или ключ
сессии): токен не является секретом, но чужой пользователь его использовать не
может. Кэш по-прежнему временный (1 час) — постоянное хранение разметки
см. раздел 9.

### `media_library/urls.py`
Маршруты (внутри `api/admin/media/`):

```
ocr/recognize/          POST — распознавание файла/области
ocr/region/             POST — разбор области (text/value/fvtable)
ocr/regions/            POST — батч-разбор областей (файл + N регионов)
ocr/pages/              POST — страницы документа (PDF → PNG)
ocr/pages/<token>/<n>/  GET  — PNG страницы n
ocr/export/             POST — экспорт результата (xlsx/docx)
ocr/export-structure/   POST — экспорт структуры (xlsx/docx)
ocr/checkbox-label/     POST — OCR подписи чек-бокса (запасной)
```

### `media_library/management/commands/preload_ocr_models.py`
`python manage.py preload_ocr_models [--lang=eslav]` — предзагрузка ONNX-моделей
RapidOCR. Нужно при сборке Docker-образа, чтобы модели лежали в volume и не
скачивались в рантайме.

## 4. OCR-движки

По умолчанию используется **RapidOCR** (onnxruntime, без системного tesseract и
без torch) — лёгкий и удобный для Docker. Для кириллицы подключена модель
`eslav_PP-OCRv5_rec_mobile`.

| Движок | Зависимости | Примечание |
|--------|-------------|------------|
| `rapidocr` | `rapidocr`, `onnxruntime` | по умолчанию, кириллица (eslav) |
| `tesseract` | системный бинарь `tesseract` + языковые пакеты | нужен apt/path, не pip-only |
| `easyocr` | `easyocr`, `torch` | тяжёлый (~2 ГБ) |
| `paddle` | `paddleocr`, `paddlepaddle` | тяжёлый |
| `surya` | `surya-ocr`, `torch` | тяжёлый |
| `doctr` | `python-doctr` | — |

## 5. Алгоритмы (ключевые)

### 5.1 Таблица F-V (`extract_fv_table`)
1. OCR слов с координатами.
2. Группировка слов по строкам (близость по Y).
3. Граница двух столбцов — максимальный горизонтальный разрыв между словами.
4. Слова слева → `field`, справа → `value`.

### 5.2 Классическая таблица
Вырезка области → `img2table` (режимы `use_first_row_as_header` и
`borderless_tables`) → `{columns, rows}`.

### 5.3 Текст области
OCR слов области → группировка по строкам (сохранение переносов строк).

### 5.4 Кэш OCR-движков (синглтоны)
Модели грузятся из файлов секундами, поэтому движки кэшируются на процесс:

- `table_extractor.get_ocr_instance()` — кэш экземпляров img2table по
  (backend, kwargs); экземпляр оборачивается в `_SerializedEngine`,
  сериализующий вызовы через RLock (модель с состоянием не потокобезопасна).
- `table_extractor.get_rapidocr_engine()` / `rapidocr_call()` — процессный
  синглтон RapidOCR (кириллица), используется `form_extractor`-ом; вызовы
  сериализованы тем же RLock.

Первый запрос в процессе по-прежнему грузит модели; все последующие — нет.

### 5.5 Чек-боксы (запасной режим `analyze_region`, в новой схеме не используется)
1. Бинаризация (адаптивный порог) → контуры.
2. Отбор квадратов: 4 угла после аппроксимации, соотношение сторон ~1,
   заполненность bounding box ≥ порога.
3. Кластеризация по медианному размеру (убирает шум от букв/цифр).
4. Дедупликация внешней/внутренней рамки.
5. Состояние: доля тёмных пикселей во внутренней области (бинаризация Оцу)
   `> 0.08` → «отмечен».

## 6. Формат JSON структуры

Холст сериализуется в JSON (готов к анализу нейросетью и под экспорт):

```json
{
  "schema_version": 2,
  "document": {
    "filename": "опросный_лист.pdf",
    "sha256": "a1b2…",
    "page_count": 3,
    "page_dims": [{ "width": 1654, "height": 2339 }]
  },
  "items": [
    {
      "kind": "section",
      "title": "ОБЩИЕ ДАННЫЕ",
      "page": 1,
      "region": { "x": 120, "y": 80, "w": 400, "h": 40 },
      "children": [
        {
          "kind": "text",
          "text": "Предприятие ООО «ЮГАЗ-Инжиниринг»",
          "page": 1,
          "region": { "x": 120, "y": 140, "w": 500, "h": 60 }
        },
        {
          "kind": "table",
          "variant": "fv",
          "page": 1,
          "region": { "x": 120, "y": 260, "w": 900, "h": 200 },
          "rows": [
            { "field": "Рабочая среда", "value": "Природный газ" },
            { "field": "Давление", "value": "1,6 МПа" }
          ]
        }
      ]
    },
    {
      "kind": "table",
      "variant": "grid",
      "page": 2,
      "region": { "x": 100, "y": 90, "w": 800, "h": 300 },
      "headers": ["Компонент", "Доля, %"],
      "rows": [
        ["Метан", "0,9720"],
        ["Этан", "0,0018"]
      ]
    }
  ],
  "text": "ОБЩИЕ ДАННЫЕ\nПредприятие ООО «ЮГАЗ-Инжиниринг»\n..."
}
```

Узлы:

- `section` — название раздела (начало блока), содержит вложенные `children`.
- `text` — произвольный распознанный текст.
- `table` + `variant: "fv"` — два столбца, список пар `rows` (field/value).
- `table` + `variant: "grid"` — классическая таблица: `headers` (пусто, если
  заголовков нет) + `rows` (список строк-массивов).
- У каждого узла: `page` (страница, с 1) и `region` (прямоугольник в пикселях
  страницы; null, если области нет).
- `document` — метаданные документа: имя, `sha256` контента (для дедупликации
  при будущем хранении), число страниц и их размеры в пикселях.
- `text` на верхнем уровне — плоская выгрузка всей структуры (для копирования).

Головной раздел в JSON не сериализуется: он всегда пустой и существует только
в интерфейсе.

## 7. Работа с инструментом

1. Загрузить изображение или PDF (слева). PDF конвертируется в страницы на
   бэкенде (`POST /ocr/pages/`); страницы листаются кнопками `‹ ›`.
2. В средней панели выбрать инструмент: `＋ Раздел`, `＋ Текст`, `＋ Таблица F-V`,
   `＋ Таблица`; для классической таблицы — опции «шапка» (первая строка —
   заголовки) и «без линий» (таблица без сетки).
3. Обвести область на текущей странице (зажать левую кнопку мыши, растянуть,
   отпустить). Область распознаётся автоматически, фрагмент появляется на
   **холсте** справа: миниатюра области + распознанное содержимое + номер
   страницы.
4. Новый раздел становится активным — следующие фрагменты попадают внутрь него.
   Клик по «Главный раздел» возвращает добавление на верхний уровень.
5. Блоки на холсте двигаются мышкой: перетащить на раздел — внутрь него, на
   другой блок — перед ним, на «Главный раздел» — на верхний уровень.
   Дублирующие кнопки: `↑/↓` (порядок), `↳/↰` (вложить/наружу), `✕` (удалить).
6. **Клик по блоку** — режим редактирования области: на изображении у фрагмента
   появляются угловые маркеры, их можно перетаскивать. В блоке — кнопки
   `⟳ Распознать` (перераспознать по новой области), `✓ Готово` (принять
   область без перераспознавания), `✕` (отменить). Esc сбрасывает редактирование.
7. **Двойной клик по блоку** — поп-ап с содержимым (текст раздела, текст
   фрагмента, таблица F-V или классическая таблица) и кнопкой `📋 Копировать`
   (текст как есть; таблицы — TSV / `поле: значение`).
8. `⟳ Распознать всё` — повторное распознавание всех блоков одним батч-запросом
   (`POST /ocr/regions/`, по одному запросу на страницу).
9. Результат: `📋/💾 JSON` (структура с геометрией и метаданными документа),
   `📋/💾 Текст` (плоский текст), `💾 Excel`, `💾 Word`. Имя файлов Excel/Word —
   как у загруженного документа (`опросный_лист.pdf` → `опросный_лист.xlsx`), с
   корректной передачей кириллицы (RFC 5987).

## 8. Ограничения

- Качество OCR зависит от модели: возможны ошибки в похожих символах
  (`1`↔`I`, `3`↔`з`, `газ`→«ра3», `зона`→«3она»).
- Объединённые ячейки таблиц `img2table` «сплющивает» в прямоугольную сетку
  (текст извлекается, но без метаданных colspan/rowspan).
- Таблица field-value: граница столбцов по максимальному разрыву — для 2 столбцов
  работает, но на длинных многословных полях возможны ошибки.
- Разметка живёт только в браузере: перезагрузка страницы теряет холст.
  Сохранить можно выгрузив JSON (`💾 JSON`); автоматическое хранение —
  см. раздел 9 (не реализовано).
- Классическая таблица распознаётся внутри обведённой области: линии сетки
  должны попадать в выделение целиком.
- Кэш страниц/результатов — временный (1 час): повторная разметка того же PDF
  требует повторной загрузки файла (постоянное хранение — раздел 9).

## 9. Хранение разметки для обучения нейросети (целевая архитектура, не реализовано)

Разметка — сырьё для обучения модели автоматической разметки. Ниже зафиксированы
решения по ключевым вопросам и целевая схема; код появится отдельным этапом.

### 9.1 Дубли: хранить или нет?

- **Файл документа дедуплицируется** по `sha256` контента (уже вычисляется на
  фронте и попадает в JSON): повторная загрузка того же файла тем же или другим
  пользователем не создаёт копию исходника — одна строка документа, страницы
  рендерятся и хранятся один раз.
- **Разметка НЕ дедуплицируется агрессивно.** Повторная разметка того же
  документа — это новый независимый «проход» (`OcrMarkupJob`): для обучения
  несколько версий одного документа — не мусор, а полезный сигнал (согласие
  разметчиков, дисперсия, оценка качества). Дедупликация применяется только
  к **идентичным** сохранениям (совпал хэш структуры — idempotent-повтор
  того же автосейва, а не новая разметка).
- Если цель — объём, а не чистота: одна разметка на документ даёт мало, зато
  несколько «шумных» проходов дешевле и пригодны для претрейна; чистую выборку
  собираем из подтверждённых (`status=confirmed`) проходов.

### 9.2 Где хранить разметку (переразметка)

- Разметка хранится **в файлах** (JSON в `storage_manager`/существующих
  `storage_backends`, рядом с медиабиблиотекой) по схеме
  `ocr-annotations/<sha256[:2]>/<sha256>/<job_uuid>.json`, плюс лёгкая индексная
  модель в БД (`OcrMarkupJob`: документ, пользователь, состояние, тайминги,
  хэш структуры). Файл — источник истины, БД — индекс для поиска.
- Переразметка = **новая версия**, старая не затирается: при загрузке уже
  известного документа интерфейс предложит открыть существующую разметку
  (загрузить последний `job`) и сохранит правки как новую версию.
- Доменная модель: `OcrDocument` (sha256, mime, страницы/размеры),
  `OcrLayoutBlock` (document, page, kind, `region` в пикселях **и**
  нормализованных `[0..1]` — канонические для обучения, `parent`, порядок,
  `payload_recognized`/`payload_corrected`, `status`), `OcrMarkupJob`.
- Для качества ground truth: распознанный текст должен быть **редактируемым**
  на холсте (сейчас только перераспознавание); правки пользователя — основной
  источник corrected-данных.

### 9.3 Экспорт датасета

Management-команда (или админ-действие) `export_ocr_dataset`:
пары «кроп + разметка» (канонический DPI), JSONL-manifest с метаданными
(движок/версия модели, confidence, `status`), split train/val **по документу**
(без утечки блоков одного документа между выборками), фильтр по `status`
и согласию на использование (`consent_for_training` на job).

### 9.4 Инференс (позже)

Модель авторазметки живёт в `ai_assistant` (там уже есть `services/`,
`prompts/` и пустой `classifiers/`), подключается за интерфейсом-реестром по
образцу `OCR_BACKENDS`; предикт показывается как предложение, не блокируя
ручную разметку.
